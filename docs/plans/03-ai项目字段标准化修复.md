# 修复计划：对齐 structured-puzzling-flask.md 的 3 处差异

## Context

数据库重构（JSON 字段转独立列）已完成大部分工作，但与原计划 `structured-puzzling-flask.md` 存在 3 处差异需要修复：

1. **迁移文件缺失** — 用 `db push` 代替了 `migrate dev`，数据库已同步但没有迁移文件历史记录
2. **formData 未精简** — 计划要求精简为 `{ applicantName, employeeId, department }`，实际仍传全量 `merged`（含 `aiPM`/`businessPM` 的 PersonSnapshot 对象）
3. **audit-decision/route.ts 计划外修改** — 计划说"不修改"，但 `valueComputation` 列已删除必须改

---

## 修复 1：创建迁移文件

**问题**：`db push` 已将 schema 应用到数据库，但没有生成迁移文件。`prisma migrate diff` 在 Prisma 7 下需要 `shadowDatabaseUrl` 才能从 migrations 目录 diff，配置较繁琐。

**方案**：手工编写迁移 SQL 文件。

**文件**：`prisma/migrations/20260924000000_aiproject_schema_normalization/migration.sql`

SQL 内容（按执行顺序）：
1. `CREATE TYPE`/`ALTER TYPE` — 新增枚举 `ProjectClassification`（PROJECT/SCENE/NON_AI），扩展 `AIProjectLevel` 增加 S_LEVEL（MySQL 用 `ALTER TABLE ... MODIFY COLUMN` 改 enum）
2. `ALTER TABLE AIProject ADD COLUMN` — 所有新增独立列（约 26 个）
3. `UPDATE` 语句 — 从 `formData` JSON 提取字段填充新列（用 `JSON_EXTRACT`）
4. `UPDATE` 语句 — 从 `coverageScope` 填充 `coverageRank`（`CAST(coverageScope AS UNSIGNED)`）
5. `UPDATE` 语句 — 从 `valueComputation` JSON 提取 `annualValue`/`firstYearValue`/`valueBreakdown`/`actualValue`/`points`/`coverageRank`/`depthRank`
6. `UPDATE` 语句 — 从 `aiAutoReview` JSON 提取 `aiDecision`/`aiLevel`/`aiClassification`/`aiCapabilityLevel`/`aiReasoning`/`aiEvidence`/`aiBlockers`/`aiSuggestions`/`aiConfidence`
7. `ALTER TABLE AIProject DROP COLUMN` — 删除 `coverageScope`/`valueComputation`/`lastRefreshedAt`

然后用 `npx prisma migrate resolve --applied 20260924000000_aiproject_schema_normalization` 标记为已应用（因为 db push 已经执行过同样的变更）。

## 修复 2：精简 formData + PersonSnapshot 独立列

**问题**：计划要求 `formData` 精简为 `{ applicantName, employeeId, department }`，但 `formData` 中包含 `aiPM`/`businessPM` 的 PersonSnapshot 对象（含 feishuOpenId/name/employeeId/orgUnitPath/avatar），详情页 `renderPerson` 需要这些数据来渲染 PersonCard。

**方案**：新增 `businessPMSnapshot`/`aiPMSnapshot` 两个 `Json?` 列存储 PersonSnapshot。`formData` 精简为只读快照。

### 2a 修改 — `prisma/schema.prisma`
在 AIProject 模型中新增：
```prisma
businessPMSnapshot        Json?    // PersonSnapshot 或 PersonSnapshot[]
aiPMSnapshot              Json?    // PersonSnapshot
```

### 2b. POST API — `src/app/api/ai-project/route.ts`
- `resolvePerson`/`resolvePersonMulti` 返回值增加 `snapshot` 字段（原始 PersonSnapshot 对象）
- Prisma create data 中新增 `businessPMSnapshot: bizPM.snapshot` / `aiPMSnapshot: aiPMResolved.snapshot`
- `formData` 改为仅含 `{ applicantName, employeeId, department }`（从 auth 用户信息中构造）

### 2c. PUT API — `src/app/api/ai-project/[id]/route.ts`
- 同 POST，`resolvePerson`/`resolvePersonMulti` 返回 snapshot
- Prisma update data 中新增 `businessPMSnapshot`/`aiPMSnapshot` 写入
- `formData` 改为仅含只读快照

### 2d. 前端申报页 — `src/app/incentive/project/apply/page.tsx`
- `buildPayload`：`formData` 从 `merged` 改为 `{ applicantName: merged.applicantName, employeeId: merged.employeeId, department: merged.department }`
- 草稿回填 `fromColumns` 映射中新增 `aiPM: p.aiPMSnapshot` / `businessPM: p.businessPMSnapshot`（PersonSelect 回填需要这些值）

### 2e. 管理详情页 — `src/app/admin/ai-project/[id]/page.tsx`
- `renderPerson(fd["aiPM"], r.aiPM)` → `renderPerson(r.aiPMSnapshot, r.aiPM)`
- `renderPerson(fd["businessPM"], r.businessPM)` → `renderPerson(r.businessPMSnapshot, r.businessPM)`
- 可删除 `const fd = (r.formData as Record<string, unknown>) || {}`（如果不再有其他 fd 引用）

### 2f. 用户详情页 — `src/app/incentive/project/detail/[id]/page.tsx`
- `renderPerson(fd["businessPM"], data.businessPM)` → `renderPerson(data.businessPMSnapshot, data.businessPM)`
- `renderPerson(fd["aiPM"], data.aiPM)` → `renderPerson(data.aiPMSnapshot, data.aiPM)`
- `ProjectDetail` 接口新增 `businessPMSnapshot`/`aiPMSnapshot` 字段
- 可删除 `const fd = data.formData || {}`（如果不再有其他 fd 引用）

### 2g. 迁移 SQL 中新增
在迁移 SQL 中新增 `businessPMSnapshot`/`aiPMSnapshot` 列定义，以及 UPDATE 语句从 `formData` JSON 中提取 `aiPM`/`businessPM` 填充新列。

## 修复 3：audit-decision/route.ts — 保留修改

此修改**必要且无法回退** — `valueComputation` 列已从 schema 删除，`audit-decision/route.ts` 必须改为从 `annualValue` 独立列读取。这是原计划的遗漏，不是实现偏差。

**不回退此修改。**
