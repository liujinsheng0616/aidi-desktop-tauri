# 二期：补齐 5 个硬件诊断命令

## Context

一期已跑通"电脑卡顿 → 自动诊断 → LLM 分析"链路，但只调用了 4 个已有命令（system_info / memory_status / disk_health / startup_list）。二期补齐缺失的 5 个诊断维度：实时性能采样、SSD 可靠性、电池健康、硬件错误日志、内存条与显卡详情。

所有现有诊断命令遵循统一模式：Rust `#[tauri::command]` 函数 → `run_script("name")` → 执行 `scripts/<name>.ps1` → 脚本输出 JSON → Rust 解析。二期完全复用此模式。

## 改动文件

### 1. 新建 5 个 PowerShell 脚本（`src-tauri/scripts/`）

每个脚本遵循现有 JSON 输出格式：`{ dimension, status, summary, details }`

**`perf-sample.ps1`**（第4步：实时性能采样）
- `Get-Counter '\Processor(_Total)\% Processor Time'` → CPU 实时占用率
- `Get-Counter '\Memory\Available MBytes'` → 可用内存 MB
- `Get-Counter '\PhysicalDisk(_Total)\% Disk Time'` → 磁盘繁忙率
- `Get-Counter '\PhysicalDisk(_Total)\Current Disk Queue Length'` → 磁盘队列长度
- 输出 `dimension: "perf"`, `status` 按 CPU>80%=danger / >60%=warning / else good

**`ssd-health.ps1`**（第7步：SSD 温度/磨损/通电时长）
- `Get-PhysicalDisk | ForEach-Object { $_ | Get-StorageReliabilityCounter }`
- 输出每块物理磁盘的：温度、磨损百分比、通电时长(小时)、读取错误数、写入错误数
- `dimension: "ssd"`, status 按 wear>80%=danger / >50%=warning / else good

**`battery-report.ps1`**（第8步：电池健康报告）
- `powercfg /batteryreport /xml /output <temp>` → 解析 XML 获取 DesignCapacity / FullChargeCapacity / CycleCount
- 计算健康度 = FullCharge / Design * 100%
- `dimension: "battery"`, status 按 health<60%=danger / <80%=warning / else good
- 无电池时 status="info", summary="无电池"

**`hw-errors.ps1`**（第9步：硬件错误事件日志）
- `Get-WinEvent -FilterHashtable @{LogName='System'; ProviderName='Microsoft-Windows-WHEA-Logger'} -MaxEvents 20`
- 再查 `Microsoft-Windows-Kernel-Power` (ID 41 = 异常关机)
- 输出最近 20 条硬件错误：时间、类型、严重级别、消息摘要
- `dimension: "hw_errors"`, status 按近7天有3+条错误=danger / 有1-2条=warning / 无=good

**`memory-gpu-diag.ps1`**（第10步：内存条与显卡详情）
- `Get-CimInstance Win32_PhysicalMemory` → 每根内存条：容量、频率、制造商、插槽
- `Get-CimInstance Win32_VideoController` → 显卡：名称、驱动版本、显存、分辨率
- `dimension: "mem_gpu"`, status="info"

### 2. 修改 Rust 后端（`src-tauri/src/lib.rs`）

在现有 `optimizer_system_info` 函数（~line 3508）之后，新增 5 个命令函数：

```rust
#[tauri::command]
async fn optimizer_perf_sample(_app: tauri::AppHandle) -> Result<serde_json::Value, String> {
    tokio::task::spawn_blocking(|| run_script("perf-sample"))
        .await.map_err(|e| format!("Task join error: {}", e))?
}

// 同理：optimizer_ssd_health, optimizer_battery_report, optimizer_hw_errors, optimizer_memory_gpu_diag
```

在 `generate_handler![...]`（line 4012-4085）中注册 5 个新命令名。

### 3. 修改前端 `src/services/dify.ts`

在 `collectDiagnosticReport()` 的 `Promise.allSettled` 数组中追加 5 个调用：

```ts
const [sysRes, memRes, diskRes, startupRes, perfRes, ssdRes, batteryRes, hwErrRes, memGpuRes] = await Promise.allSettled([
  invokeFn('optimizer_system_info'),
  invokeFn('optimizer_memory_status'),
  invokeFn('optimizer_disk_health'),
  invokeFn('optimizer_startup_list'),
  invokeFn('optimizer_perf_sample'),      // 第4步
  invokeFn('optimizer_ssd_health'),        // 第7步
  invokeFn('optimizer_battery_report'),   // 第8步
  invokeFn('optimizer_hw_errors'),         // 第9步
  invokeFn('optimizer_memory_gpu_diag'),  // 第10步
])
```

在 `formatDiagnosticReport` 的 `parts` 数组中追加 5 个新的格式化区块，与一期已有的 4 个区块平行。

### 4. 修改 `src/config/itAssistScenes.ts`

在 `performance_diagnostic` 场景的 `systemPromptFragment` 分析维度中追加：

- 6. **实时性能**：CPU 实时占用 >80% 或磁盘队列 >2 提示过载
- 7. **SSD 磨损**：SSD 磨损 >50% 或通电 >30000 小时提示更换
- 8. **电池健康**：健康度 <80% 提示更换电池
- 9. **硬件错误**：近 7 天有 WHEA 错误提示硬件故障风险
- 10. **内存条配置**：内存条频率不一致或容量不均提示优化配置

## 不做的事

- 不修改 `tauri.conf.json`（`"resources": ["scripts/*"]` 已包含所有新增脚本）
- 不修改 `build.rs`（现有配置已处理脚本复制）
- 不修改 capabilities（自定义命令在 Tauri 2 中可从任何窗口调用）
- 不修改 macOS 的 `.sh` 脚本（这些诊断命令是 Windows 专用的，Mac 上 `Promise.allSettled` 会容错）

## 验证

1. `cargo check`（在 `src-tauri/`确认 Rust 编译通过
2. `npx vue-tsc --noEmit` 确认前端类型检查通过
3. IDE 诊断无错误
4. 在 Windows Tauri 应用中输入"电脑卡顿"：
   - 控制台可见 9 个 `invoke` 调用被发起
   - Dify 请求体中 `diagnostic_report` 包含全部 9 个区块
5. 在 Mac 上输入"电脑卡顿"：
   - 9 个 invoke 全部失败但 `allSettled` 容错
   - `diagnostic_report` 为空字符串，LL 走降级引导
6. 输入"打印机连接"不触发诊断
