## 发现的问题

### BUG 1 [严重] AI 审核注入逻辑：applicantId 缺失导致确定性数据全部丢失

**文件**: `src/app/api/ai/audit-decision/route.ts` (行 33-34) + `src/app/incentive/certification/apply/[level]/page.tsx` (行 85)

**根因**: 前端 `runReview` 发送 `application: { level, ...formValues }` 到 `/api/ai/audit-decision`。`formValues` 来源于表单 schema，包含 `applicantName`、`employeeId`、`orgUnit`、`department`、`currentCertLevel`、`examScore`、`scenes`、`，但**不包含 `applicantId`**（用户数据库内部 ID）。

`auth/me` 接口返回 `id` 字段，但前端 `useEffect` 没有将 `u.id` 映射到 `formValues.applicantId`。

后端 `injectYellowBeltComputedValues` 函数第 33-34 行：
```ts
const applicantId = application.applicantId as string | undefined;
if (!applicantId) return computedValues ?? {};  // ← 提前返回！
```

由于 `applicantId` 为 `undefined`，函数在第 34 行提前返回空对象。导致以下确定性数据**全部不被注入**：
- `examPassed`（考试是否 >=80）
- `sceneCount`（场景数量）
- `sceneTargetMet`（场景是否 >=3）
- `currentCertLevel`（当前认证等级）
- `（结构化场景数组）

AI 审核提示词要求"系统已预计算以下值，直接使用，不要重算"，但这些值实际为空。AI 审核员无法获得必要的判据。

**影响范围**: 黄带、绿带、黑带三个认证的 AI 审核均受影响（同样的提前返回模式存在于 `injectGreenBeltComputedValues` 和 `injectBlackBeltComputedValues`）。

**修复方案（二选一）**:

方案 A（推荐）：修改 `injectYellowBeltComputedValues`，将不依赖 `applicantId` 的计算移到 early return 之前：
```ts
async function injectYellowBeltComputedValues(application, computedValues) {
  const examScore = typeof application.examScore === "number" ? application.examScore : null;
  const scenes = Array.isArray(application.scenes) ? application.scenes : [];
  const sceneCount = scenes.length;
  const examPassed = examScore != null && examScore >= 80;
  const sceneTargetMet = sceneCount >= 3;

  const applicantId = application.applicantId as string | undefined;
  if (!applicantId) {
    return { ...computedValues, examPassed, sceneCount, sceneTargetMet, scenes };

  const currentCertLevel = await getUserCertLevels(applicantId);
  return { ...computedValues, examPassed, sceneCount, sceneTargetMet, currentCertLevel, scenes };
}
```

方案 B：修改前端 `apply/[level]/page.tsx` 的 `useEffect`，在 `basic` 对象中加入 `applicantId: u.id ?? ""`，确保 payload 包含 `applicantId`。

建议同时执行 A + B，双保险。

### BUG 2 [严重] 黄带 PATCH 人工通过时未写入 UserCertification

**文件**: `src/app/api/yellow-belt/[id]/route.ts` (行 89-107)

**根因**: 绿带 PATCH（`green-belt/[id]/route.ts` 行 92-113）和黑带 PATCH（`black-belt/[id]/route.ts` 行 89-111）在人工通过时都调用 `prisma.userCertification.upsert()` 写入认证等级（"绿带"/"黑带"）。

但黄带 PATCH 的人工通过逻辑（行 89-107���只做了两件事：
1. 写入 `certValidUntil: "永久有效"`
2. 补发头像框

**缺少** `prisma.userCertification.upsert()` 调用，不写入 "黄带" 等级记录。

**后果**:
- 用户通过黄带认证后，`UserCertification` 表无 "黄带" 记录
- `getUserCertLevels()` 查询返回 null/空
- 后续该用户申请绿带时，`injectGreenBeltComputedValues` 中的 `currentCertLevel` 为 null
- AI 绿带审核提示词要求"已有黄带"作为前置条件，但系统无法提供此信息
- 绿带 AI 审核可能因缺少前置认证数据而误判

**修复方案**: 在黄带 PATCH 的 `if (decision === "PASS")` 块中，添加 UserCertification upsert：
```ts
if (decision === "PASS") {
  await Promise.all([
    prisma.yellowBeltApplication.update({
      where: { id },
      data: { certValidUntil: "永久有效" },
    }),
    prisma.userCertification.upsert({
      where: {
        userId_level: { userId: existing.applicantId, level: "黄带" },
      },
      update: { validUntil: null, grantedAt: new Date() },
      create: {
        userId: existing.applicantId,
        level: "黄带",
        grantedAt: new Date(),
      },
    }),
  ]);
  // ... 补发头像框逻辑
}
```

注意：黄带 `certValidUntil` 设为 "永久有效"（非日期格式），`UserCertification.validUntil` 应设为 `null` 或一个特殊值，需根据 `UserCertification` 模型字段类型决定。

YellowBeltStatus 枚举（7 态：DRAFT/SUBMITTED/AI_APPROVED/AI_REI_NEED_INFO/HUMAN_APPROVED/HUMAN_REJECTED）与 API 实现一致。POST 路由正确设置 `applicantId`、`examScore`、`scenes`、`personnelCategory` 等字段。

`DRAFT → SUBMITTED → AI_APPROVED/AI_REJECTED/AI_NEED_INFO → HUMAN_APPROVED/HUMAN_REJECTED` 流转正确：
- POST 路由设置 `status: "SUBMITTED"`

- `AI_APPROVED` 时预发放头像框，`HUMAN_REJECTED` 时撤回头像框
- 终态 `HUMAN_APPROVED` / `HUMAN_REJECTED` 不可逆

### 4. 遗留引用清理
全量搜索 `TalentApplication`、`TalentLevel`、`ThreeModuleStatus` 在 `src/` 和 `prisma/schema.prisma` 中均无匹配。已完全清理。

### 5. AI 提示词与业务逻辑匹配
`YELLOW_BELT_AUDITOR_PROMPT` 正确描述了黄带认证条件（考试 >=80 + >=3 场景）、场景有效性校验规则（防拆分/必须用 AI/必须有佐证/频繁使用/本职关联）。`YELLOW_BELT_OUTPUT_SCHEMA` 输出契约正确（decision/level/reasoning/evidence/blockers/suggestions/reviewerNotes/confidence）。`getAuditorPrompt` 的 `yellow-belt` case 正确映射到 `YELLOW_BELT_AUDITOR_PROMPT`。

### 6. 前端表单 Schema
`SchemaConfig.ts` 的 `yellowSchema` 正确定义了 `examScore`（number, 0-100）、`scenes`（structuredList, minItems: 3, 含 taskName/aiTool/beforeAfter/jobRelevance/evidence）、`remark` 等字段，与 Prisma 模型和 AI 提示词一致。

### 7. 管理后台 AdminListPage 骨架

### 8. 管理后台 API 过滤
`admin/yellow-belt/applications/route.ts` 正确映射了 `PENDING`/`PASS`/`REJECT`/`NEED_INFO` 状态筛选到 YellowBelt 枚举值。权限控制通过 `requireAdminOrCollab` + `resolveAdminScope` 正确实现。

### 9. parseAuditResult 解析
JSON 解析使用三策略（代码块提取 → 从最后 `}` 逐步尝试 → 整体解析），fallback 为 null（不再伪造 NEED_INFO），设计合理。
