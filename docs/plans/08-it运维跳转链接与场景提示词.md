# IT 运维跳转链接：关键词分层 + 场景提示词注入

## Context

用户需要在悬浮球聊天中添加 IT 运维流程跳转链接（电脑借领用、委外维修等）。核心约束：`enable_wiki_search` 开关控制 Dify 知��库检索，关闭时 LLM 无法获取飞书文档内容。因此业务判断规则必须前置在前端配置中，通过 Dify inputs 注入。同时不能全量注入所有场景规则（浪费 token、干扰 LLM），需按关键词匹配只注入命中场景的提示词片段。

## 架构设计

### 数据流

```
用户输入 query
    ↓
前端关键词匹配 IT_ASSIST_SCENES
    ↓
命中 → 拼接命中场景的 systemPromptFragment → inputs.it_ops_fragment
未命中 → inputs.it_ops_fragment = ""（空字符串）
    ↓
Dify 工作流接收 it_ops_fragment + enable_wiki_search（原样透传）
    ↓
LLM 依据注入片段判断 + 可选 wiki 检索 → 回复 + markdown 链接
```

### 与 enable_wiki_search 的关系（完全独立）

| enable_wiki_search | 命中 IT 场景 | 行为 |
|---|---|
| true | ✅ | 注入规则片段 + wiki 检索，双重保障 |
| true | ❌ | it_ops_fragment 为空，纯 wiki 检索（原有逻辑不变） |
| false | ✅ | 注入规则片段，LLM 靠内置规则判断 |
| false | ❌ | it_ops_fragment 为空，纯模型回复（原有逻辑不变） |

## 实施步骤

### 第 1 步：新建 `src/config/itAssistScenes.ts`

替换现有的 `itOpsGuide.ts`，改为结构化的场景配置数组：

```typescript
interface ItAssistScene {
  sceneId: string
  keywords: string[]
  systemPromptFragment: string
  links: Array<{ title: string; url: string }>
  requireLLMJudge: boolean
}
```

两个场景：
- **电脑借领用**（`requireLLMJudge: false`）：关键词命中后直接给链接
- **资产委外维修**（`requireLLMJudge: true`）：8 条标准写在 systemPromptFragment 里，LLM 对照判断

### 第 2 步：修改 `src/services/dify.ts`

1. 导入 `IT_ASSIST_SCENES`
2. 在 `sendChatMessage` 中做关键词匹配：
   ```typescript
   const hitScenes = IT_ASSIST_SCENES.filter(scene =>
     scene.keywords.some(kw => query.includes(kw))
   )
   const itOpsFragment = hitScenes.length > 0
     ? hitScenes.map(s => s.systemPromptFragment).join('\n-----\n')
     : ''
   ```
3. inputs 中把 `it_ops_guide: IT_OPS_GUIDE` 改为 `it_ops_fragment: itOpsFragment`
4. 删除旧的 `import { IT_OPS_GUIDE } from '@/config/itOpsGuide'`

### 第 3 步：删除 `src/config/itOpsGuide.ts`

被 `itAssistScenes.ts` 替代。

### 第 4 步：Dify 后台配置

在工作流 Agent 节点系统提示词中引用 `{{#start.it_ops_fragment#}}`（替代之前的 `it_ops_guide`）。

提示词模板：
```
你是IT助手。

{{#start.it_ops_fragment#}}

规则：
1. 如果 it_ops_fragment 不为空，优先遵循片段内业务指令，输出对应的链接
2. enable_wiki_search 控制是否检索知识库，与 it_ops_fragment 逻辑无关
3. 输出链接必须使用 markdown 格式 [文字](URL)
```

### 第 5 步：验证

用 curl 测试 4 组 case：
1. 关闭 wiki + "电脑借用怎么申请" → 回复含 IS-37 链接
2. 关闭 wiki + "电脑进水了能修吗" → LLM 对照 8 条标准判断，回复含 PC-22 链接
3. 关闭 wiki + "电脑维修过"（陈述事实）→ 不应给链接
4. 开启 wiki + "电脑进水了" → 注入规则 + wiki 检索双重保障

## 为什么不做运行时飞书 API 调用

1. 每次聊天额外网络请求，增加响应延迟
2. 飞书 token 过期、鉴权异常、网络失败都需要兜底处理
3. IT 流程规则变更频次低，人工维护代码配置 + 版本迭代完全够用
4. 当前场景数量少（2 个，未来 5-10 个），写死在配置文件里可控

## 未来扩展

新增 IT 流程场景只需在 `IT_ASSIST_SCENES` 数组中追加一项配置，包含关键词、提示词片段、链接。无需改其他代码，无需改 Dify 后台。
